# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выходят только для последних релизов:

- `mcp-yandex-kit` и `yandex-kit-core` — последние версии, опубликованные в npm;
- скиллы и плагин — последний релиз этого репозитория.

Старые версии не поддерживаются. Прежде чем сообщать о проблеме, проверьте,
воспроизводится ли она на последней версии.

## Как сообщить об уязвимости

Только приватно, через GitHub Security Advisories этого репозитория:
вкладка **Security** → **Report a vulnerability**. Не создавайте публичный
issue и не публикуйте детали до выхода исправления.

## Что считается уязвимостью здесь

- утечка токена магазина (`YANDEX_KIT_TOKEN`) в логи, вывод инструментов,
  телеметрию или файлы конфигурации;
- обход валидации записи: мутация уходит в API без проверки тела запроса или
  минуя контракт «чтение → одна запись → проверочное чтение»;
- выполнение команд из недоверенного текста в данных магазина (примечания к
  доставке, описания товаров и т. п.);
- поломка бэкапа или отката клиентского конфига в setup-скилле: установка
  без бэкапа изменённого конфига или откат, восстанавливающий не то состояние.

Обычные ошибки без границы безопасности (неверный ответ API, опечатка в
скилле, упавший тест) — это GitHub Issues.

## Чего ожидать

Мы стараемся подтвердить получение и дать первичную оценку в течение
нескольких рабочих дней, а исправление — в разумный срок в зависимости от
серьёзности. Программы bug bounty у проекта нет.

## Просьба

Не проверяйте гипотезы на чужих боевых магазинах: каждый вызов API уходит в
реальный магазин, а созданный товар нельзя удалить. Используйте собственный
тестовый магазин.
