# Техническое устройство

Корневой README описывает пользовательские задачи. Здесь собраны внутреннее устройство, покрытие API и эксплуатационные ограничения проекта.

## Компоненты

Проект состоит из трёх уровней:

1. **`yandex-kit-core`** — типизированный клиент публичного API Яндекс KIT. Реестр операций и типы генерируются из сохранённой OpenAPI-спецификации.
2. **`mcp-yandex-kit`** — stdio MCP-сервер, который предоставляет операции клиента AI-приложению.
3. **Agent Skills** — инструкции для выбора операций и выполнения пользовательских сценариев. Шесть навыков отвечают за домены API, четыре — за готовые сценарии магазина, один — за установку.

## Покрытие API

| Показатель | Значение |
| --- | ---: |
| MCP-инструменты | 61 |
| Операции со специализированными инструментами | 65 |
| Операции без специализированного инструмента | 68 |
| Всего операций в сохранённой спецификации | 133 |
| Agent Skills | 11 |

Число инструментов и число специализированных операций не обязаны совпадать: один инструмент может выбирать несколько связанных операций по действию.

Для операций без отдельного инструмента используется мета-трио:

- `search_operations` ищет операции по `operationId`, пути, тегу и русскому описанию;
- `get_operation_schema` возвращает метод, путь, параметры, content type и развёрнутые схемы запроса и ответа;
- `kit_request` выполняет операцию по `operationId`.

Полная карта инструментов и список остальных 68 операций генерируются в [TOOLS.md](TOOLS.md).

## Проверка запросов

- JSON-тела специализированных write-инструментов и `kit_request` валидируются по JSON Schema сохранённой OpenAPI-спецификации с помощью AJV до обращения к сети.
- Пустые обновления отклоняются.
- Для каждой операции используется указанный в спецификации content type, включая `application/merge-patch+json` и `multipart/form-data`.
- Read-only инструменты помечаются аннотациями для MCP-клиента.
- `kit_request` предоставляет полный доступ к API и поэтому сам по себе не считается read-only: безопасность определяется выбранной операцией.

Навыки добавляют поверх этого поведенческую границу: обзорные запросы не вызывают write-инструменты, а бизнес-значения для изменений не выводятся из догадок.

## Сетевой клиент

Клиент использует Bearer-токен и по умолчанию:

- ограничивает поток до 3 запросов в секунду;
- применяет таймаут 30 секунд к каждой попытке;
- автоматически проходит пагинацию там, где это предусмотрено обёрткой;
- повторяет только GET-чтения после сетевой ошибки, таймаута, HTTP 429, HTTP 5xx или ошибки `LIMIT_EXCEEDED`;
- учитывает `Retry-After`, когда сервер его возвращает;
- использует экспоненциальную задержку между остальными повторными попытками.

`LIMIT_EXCEEDED` у Яндекс KIT может приходить как HTTP 400. POST, PATCH, PUT и DELETE не повторяются автоматически: после таймаута сервер мог уже применить изменение, а повтор создал бы дубликат или вторую мутацию.

## Конфигурация сервера

| Переменная | Обязательна | По умолчанию | Описание |
| --- | :---: | --- | --- |
| `YANDEX_KIT_TOKEN` | да | — | API-токен магазина. |
| `YANDEX_KIT_BASE_URL` | нет | `https://api.kit.yandex.net` | Базовый URL API. |
| `YANDEX_KIT_RPS` | нет | `3` | Пропускная способность token bucket, запросов/с. |
| `YANDEX_KIT_TIMEOUT_MS` | нет | `30000` | Таймаут одной HTTP-попытки, мс. |

Канонический запуск опубликованного сервера:

```text
npx -y mcp-yandex-kit@latest
```

Пользовательский путь и правила работы с токеном вынесены в [INSTALLATION.md](INSTALLATION.md).

## Ограничения внешнего API

- API ограничивает магазин тремя запросами в секунду.
- Песочницы нет: обычное подключение работает с боевым магазином.
- Публичный API находится в статусе беты, поэтому контракт может меняться. Снимок спецификации хранится в репозитории, а CI проверяет дрейф сгенерированных файлов.
- Секрет вебхука возвращается только при создании. Алгоритм проверки подписи входящих запросов Яндексом в используемой спецификации не документирован.
- API не предоставляет настройки оплаты и доставки и не позволяет launch-check самостоятельно создать и оплатить тестовый заказ.

## Генерация и проверки

Codegen создаёт реестр операций, TypeScript-типы, доменные навыки и [TOOLS.md](TOOLS.md) из сохранённой OpenAPI-спецификации. CI работает на Node.js 20, 22 и 24 и проверяет:

- типы и сборку;
- модульные и сценарные тесты;
- setup-сценарий;
- отсутствие дрейфа сгенерированных файлов.

Live E2E запускается отдельно только при наличии секретного токена тестового магазина.
