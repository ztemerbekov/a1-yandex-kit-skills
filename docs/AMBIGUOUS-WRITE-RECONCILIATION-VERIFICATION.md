# Проверка сверки неоднозначной записи

Дата: 2026-10-09. Проверка выполнена офлайн на сценариях с поддельным хранилищем;
боевые вызовы KIT не выполнялись.

| Сценарий | Записи | Чтения | Результат |
| --- | ---: | ---: | --- |
| `CreateCollection` сохранил объект, затем вернул HTTP 429 | `GET → POST(429) → GET → verify`, 1 POST | preflight и полное чтение после POST | найден один полный объект `created-1`; его ID добавлен в readback-сообщение, ACK текущей записи остаётся неизвестным, второй POST не выполняется |
| HTTP 429 без сохранения | `GET → POST(429) → GET → verify`, 1 POST | preflight и полное чтение после POST | совпадений нет; результат `ambiguous`, повтор не выполняется |
| Два полных совпадения | `GET → POST(429) → GET → verify`, 1 POST | preflight и полное чтение после POST | конфликт; второй POST не выполняется |
| Тот же title, но другой `dynamic_filter` | `GET → POST(429) → GET → verify`, 1 POST | preflight и полное чтение после POST | совпадение отклонено; результат `ambiguous`, второй POST не выполняется |
| Сбой или неполное чтение после записи | `GET → POST(429) → GET(error)`, 1 POST | readback прерван | результат `ambiguous`, позиция сохраняется для последующей сверки |
| HTTP 400 `LIMIT_EXCEEDED` | 1 POST | контракт ошибки и классификатор | исход неизвестен; автоматическая повторная запись запрещена |

Для коллекции сравниваются `collection_type: DYNAMIC`, полный канонический
`dynamic_filter` с `category_slugs` и `characteristic_filters`, поля плана
(`status`, `title`, переданный `slug` и фильтр) и IDs, собранные до записи.
Проверка канонизирует порядок ключей объекта фильтра; preflight ID не считается
новым совпадением. Одного title или slug недостаточно: суффикс slug не доказывает
отсутствие дубликата. Один полный надёжный match можно принять по его ID, не
утверждая, что его создал текущий запуск.

Проверка покрывает также общий MCP envelope: для попытанной mutation ошибки
сохраняются `error`, `code`, `status`, `traceId` и добавляются
`operation_id`, `method`, `mutation_outcome: "unknown"`, `readback_required: true`,
`repeat_policy: "do_not_repeat"`. Ошибки GET и локальная validation-before-network
не получают mutation-specific поля. Таймауты, сетевые ошибки, 408, 5xx, 429,
400 `LIMIT_EXCEEDED` и ошибочный JSON успешного ответа остаются неоднозначными.

Тесты фиксируют процедурную fake-трассу (`GET`/`POST`/`verify`), счётчики и
наблюдённые бизнес-ID. Это проверка протокола сверки, а не оценка поведения LLM
или качества интерпретации сгенерированных инструкций.

Ограничение: сценарии моделируют опасный исход и не доказывают, что конкретный
боевой ответ KIT означает сохранение записи. Наличие объекта после 429 принимается
как наблюдение readback, а не как надёжное подтверждение ACK текущего POST.
