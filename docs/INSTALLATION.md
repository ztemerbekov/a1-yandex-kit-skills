# Установка и подключение

Эта инструкция дополняет короткий путь из корневого README. Основной сценарий рассчитан на пользователя AI-приложения; ручная настройка внизу страницы предназначена для технических специалистов.

## Что понадобится

- магазин на Яндекс KIT;
- Node.js 20.11+ и рабочая команда `npx`;
- токен магазина из **Настройки → API**;
- одно из поддерживаемых AI-приложений либо клиент с документированной поддержкой MCP.

Setup-навык работает на Node.js и сам его не устанавливает. Если Node.js или `npx` недоступны, навык даёт одну подходящую для операционной системы инструкцию и останавливается без запроса токена и изменения конфигурации. Node.js нужен ещё раньше для команды `npx skills add`.

## Перед подключением

Токен Яндекс KIT:

- даёт полный доступ к магазину, включая каталог, цены и заказы;
- при настройке через файловый конфиг сохраняется в пользовательском конфиге AI-приложения открытым текстом;
- если передать токен в чат по своему выбору, он останется в истории чата;
- в удалённой сессии его можно задать в переменной окружения или настройках секретов — тогда он не попадает в переписку;
- не должен попадать в публичные файлы, логи или репозиторий.

## Agent Plugins 1.0.0

В репозитории есть portable-пакет стандарта [Agent Plugins](https://agent-plugins.org/):
корневой `plugin.json` описывает пакет, `skills/` содержит навыки, а `mcp.json`
описывает stdio-сервер `yandex-kit`. Этот portable `mcp.json` не содержит токен и
не подставляет его через shell-конструкции: стандарт не задаёт универсальный способ
хранить credentials.

Если клиент поддерживает Agent Plugins, используйте его документированный способ
установки пакета, а затем выполните setup-сценарий для передачи токена клиенту.
Клиентские адаптеры `.codex-plugin/`, `.cursor-plugin/`, `.claude-plugin/`,
`.agents/` и `.mcp.json` сохраняются для клиентов, которым нужен их собственный
формат. Они не являются заменой portable-файлам и не удаляются автоматически.

Собственной песочницы у проекта нет. После подключения чтения и изменения обращаются к боевому магазину.

## Основной путь

1. Установите Node.js 20.11+, если он ещё не установлен.

2. Откройте терминал. На Windows используйте Windows Terminal, PowerShell или Command Prompt; на macOS и Linux — обычный терминал. Одна и та же команда работает во всех этих оболочках:

   ```bash
   npx skills@latest add ztemerbekov/a1-yandex-kit-skills -y
   ```

3. Явно вызовите навык `a1-yandex-kit-setup`. В Codex используйте:

   ```text
   $a1-yandex-kit-setup
   ```

   В другом AI-приложении явно выберите навык с этим именем в списке команд. Голосовая или текстовая фраза **«Подключи Яндекс KIT»** без явного выбора навыка установщик не запускает.

4. Если приложение нельзя определить автоматически, ассистент спросит, куда подключить магазин.
5. Setup-сценарий проверит Node.js и `npx` до запроса токена и изменения настроек.
6. Когда setup выберет маршрут токена, получите его в кабинете продавца: **Настройки → API**. На локальном компьютере setup откроет страницу в постоянной штатной панели выбранного приложения, если такая возможность доступна: в Codex это браузерная панель приложения, в Claude Code — встроенная Browser/preview-панель. Временные вкладки автоматизации и управление экраном для этой страницы не используются, потому что они могут закрыться вместе с ответом ассистента. Если штатная панель недоступна или не может добраться до loopback, setup попробует браузер по умолчанию операционной системы, а при неуверенности даст ссылку для открытия вручную. Браузер и setup должны работать на одном компьютере: наличие встроенного браузера само по себе не доказывает доступ к loopback из удалённой или виртуальной сессии. В удалённой сессии используйте настройки секретов или окружения; чат-маршрут доступен только после явного выбора владельца. Ассистент не должен повторять токен в ответах или диагностике.
7. Токен, полученный через одноразовую страницу или явно выбранный чат-маршрут, будет проверен до сохранения настроек, чтобы убедиться в доступе к магазину. Неверный токен не записывается в конфиг.
8. После настройки сценарий проверит подключение выбранными для приложения документированными командами и read-only проверкой. Проверка подтверждает MCP-подключение и доступ к магазину, не меняя данные.
9. Setup предложит один раз включить **«Работу без остановок»**. После согласия AI-приложение разрешит все текущие и будущие инструменты Yandex KIT без повторных Allow, включая удаления, заказы, промоакции и настройки магазина. Рабочие навыки по-прежнему выполняют изменения только по точной команде пользователя.
10. Если клиент нельзя перезагрузить документированной командой, ассистент даст одну короткую инструкцию по перезапуску.

Подключение считается завершённым только после сообщения, что проверка магазина прошла.

## Поддерживаемые клиенты

Для готовых профилей setup-сценарий умеет определить пользовательский конфиг и проверить результат:

- Claude Code;
- Claude Desktop;
- Cursor;
- OpenAI Codex;
- VS Code;
- Kimi Code;
- Kimi Desktop;
- Hermes Agent;
- OpenClaw.

Конкретные пути и ограничения по операционным системам перечислены в [профилях клиентов](../skills/a1-yandex-kit-setup/references/client-profiles.md).

## Работа без повторных Allow

Подтверждения показывает само AI-приложение до вызова инструмента. Это отдельный
слой от токена Яндекс KIT и от разрешения, которое вы дали ассистенту своей
командой.

После подключения setup один раз предупреждает о полном доступе к Yandex KIT и
предлагает server wildcard:

- Claude Code, Codex и Kimi Code настраиваются автоматически;
- Cursor настраивается автоматически только после проверки установленной схемы
  разрешений и фактического имени MCP-сервера;
- VS Code и Claude Desktop требуют одного шага в интерфейсе, если установленная
  версия умеет постоянно доверять всему MCP-серверу;
- Kimi Desktop, Hermes и embedded OpenClaw пока не умеют одновременно отключить
  остановки для импорта и сохранить отдельные подтверждения опасных действий.

После явного согласия setup включает wildcard только для управляемого сервера
Yandex KIT. В Cursor это `yandex-kit:*` и `user-yandex-kit:*`; в других клиентах
используется их эквивалент server-wide approval. Глобальный YOLO или Full access
для всех инструментов приложения не включается.

Проверить или повторно настроить этот режим можно тем же навыком
`a1-yandex-kit-setup`, сказав: **«Разреши все действия Yandex KIT без повторных Allow»**.

## Что именно меняет setup-сценарий

Setup-сценарий добавляет или обновляет только управляемую запись Яндекс KIT в пользовательской конфигурации выбранного клиента. Другие MCP-серверы и посторонние настройки должны сохраниться.

Для поддерживаемого файлового конфига сценарий:

- проверяет, что файл можно безопасно разобрать;
- создаёт резервную копию существующего изменяемого файла;
- на POSIX-системах задаёт изменённому конфигу и резервной копии права `0600`;
- проверяет результат записи;
- при ошибке откатывает только изменение текущего запуска и только при совпадении контрольных хешей.

Резервная копия относится только к конфигу AI-приложения. Она не является копией магазина и не позволяет откатить операции в Яндекс KIT.

Если проектная запись `yandex-kit` перекрывает пользовательскую, setup-сценарий оставляет её без изменений и использует имя `a1-yandex-kit-global`.

## Повторный запуск и замена токена

Если Яндекс KIT уже настроен, ассистент должен спросить:

> Токен Яндекс KIT уже сохранён в настройках. Вы хотите его обновить?

- Ответ **«нет»** завершает сценарий без изменения, нормализации или повторной проверки конфига.
- Ответ **«да»** запускает новый одноразовый маршрут страницы и открывает свежую страницу по тому же порядку: встроенный браузер текущей сессии, браузер операционной системы, затем кликабельная ссылка. Старую страницу повторно не используют. Чат-маршрут не предлагается как обычный вариант; он доступен только после явного выбора владельца, если защищённый маршрут недоступен.

Setup-сценарий не является универсальным ремонтом MCP-конфигурации. Повреждённый или изменившийся формат проходит проверку совместимости, а не исправляется вслепую.

## Другой или изменившийся клиент

Для клиента без готового профиля используется последовательность:

1. документированная команда клиента для добавления MCP-сервера;
2. документированный пользовательский файл поддерживаемого формата;
3. техническая передача с найденной официальной документацией и точными следующими действиями.

Неизвестный формат не редактируется методом проб и ошибок. Полные правила находятся в [описании совместимости](../skills/a1-yandex-kit-setup/references/compatibility.md).

## Ручное подключение для специалиста

Setup-сценарий всегда использует одну каноническую команду сервера:

```text
npx -y mcp-yandex-kit@latest
```

В терминах конфигурации MCP нужны следующие значения:

```text
command: npx
args: -y, mcp-yandex-kit@latest
env: YANDEX_KIT_TOKEN=<токен магазина>
```

Формат и путь конфига зависят от клиента. Не вставляйте универсальный JSON-фрагмент в неизвестный файл: используйте официальную документацию приложения или проверенный профиль setup-сценария. Токен всё равно будет храниться в конфиге открытым текстом.

Доступные переменные окружения:

| Переменная | Обязательна | Значение по умолчанию | Назначение |
| --- | :---: | --- | --- |
| `YANDEX_KIT_TOKEN` | да | — | API-токен магазина. |
| `YANDEX_KIT_BASE_URL` | нет | `https://api.kit.yandex.net` | Базовый URL API. |
| `YANDEX_KIT_RPS` | нет | `3` | Лимит исходящих запросов в секунду. |
| `YANDEX_KIT_TIMEOUT_MS` | нет | `30000` | Таймаут одной попытки HTTP-запроса, мс. |

Не передавайте токен прямо в shell-команде: он может сохраниться в истории терминала.

## Обновление

Запись использует пакет `mcp-yandex-kit@latest`, поэтому при следующих запусках клиент разрешает актуальную опубликованную версию. Отдельная команда обновления MCP-сервера не требуется.

Новые версии и изменения публикуются в [GitHub Releases](https://github.com/ztemerbekov/a1-yandex-kit-skills/releases).

Доменный навык `a1-yandex-kit-marketing` переименован в
`a1-yandex-kit-promotions`. Если вы вызывали его явно через
`$a1-yandex-kit-marketing` или `/a1-yandex-kit-marketing`, замените имя на
`$a1-yandex-kit-promotions` или `/a1-yandex-kit-promotions`: старое имя больше не
поставляется.

## Если подключение не завершилось

- **Нет Node.js или `npx`.** Setup-навык не устанавливает Node.js. Установите актуальную LTS-версию [Node.js](https://nodejs.org/), перезапустите AI-приложение и снова явно вызовите `a1-yandex-kit-setup`.
- **Токен не прошёл проверку.** Создайте или скопируйте действующий токен в **Настройки → API** и передайте его повторно. Текущий конфиг до успешной проверки не меняется.
- **Конфиг повреждён или формат изменился.** Setup-сценарий не переписывает его вслепую: он проверит официальный CLI, документированный файл или подготовит техническую передачу.
- **Сервер подключён, но клиент его не видит.** Выполните ровно ту инструкцию по перезапуску, которую вернул setup-сценарий для выбранного клиента.
- **Есть проектная запись с тем же именем.** Setup-сценарий должен использовать `a1-yandex-kit-global`, не удаляя локальную запись.

Технические параметры сервера и сетевое поведение описаны в [TECHNICAL.md](TECHNICAL.md).
