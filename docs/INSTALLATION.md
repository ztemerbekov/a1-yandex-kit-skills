# Установка и подключение

Эта инструкция дополняет короткий путь из корневого README. Основной сценарий рассчитан на пользователя AI-приложения; ручная настройка внизу страницы предназначена для технических специалистов.

**Проектный режим Codex/Claude Code добавлен в 1.12.0.** Для него нужны `yandex-kit-core`, `mcp-yandex-kit` и навык `a1-yandex-kit-setup` версии 1.12.0 или новее из одного согласованного выпуска. Перед использованием `mcp-yandex-kit@latest` убедитесь, что он разрешается в совместимую версию не ниже 1.12.0.

## Что понадобится

- магазин на Яндекс KIT;
- Node.js 20.11+ и рабочая команда `npx`;
- токен магазина из **Настройки → API**;
- одно из поддерживаемых AI-приложений либо клиент с документированной поддержкой MCP.

Setup-навык работает на Node.js и сам его не устанавливает. Если Node.js или `npx` недоступны, навык даёт одну подходящую для операционной системы инструкцию и останавливается без запроса токена и изменения конфигурации. Node.js нужен ещё раньше для команды `npx skills add`.

## Перед подключением

Токен Яндекс KIT:

- даёт полный доступ к магазину, включая каталог, цены и заказы;
- в проектном режиме Codex/Claude Code хранится в приватной записи вне репозитория; проектный файл и аргументы MCP токена не содержат;
- в прежнем пользовательском режиме сохраняется в конфиге AI-приложения открытым текстом;
- если передать токен в чат по своему выбору, он останется в истории чата;
- в удалённой сессии его можно задать в переменной окружения или настройках секретов — тогда он не попадает в переписку;
- не должен попадать в публичные файлы, логи или репозиторий.

## Agent Plugins 1.0.0

В репозитории есть portable-пакет стандарта [Agent Plugins](https://agent-plugins.org/):
корневой `plugin.json` описывает пакет, `skills/` содержит навыки, а `mcp.json`
описывает stdio-сервер `yandex-kit`. Этот portable `mcp.json` не содержит токен и
не подставляет его через shell-конструкции: стандарт не задаёт универсальный способ
хранить credentials.

Если клиент поддерживает Agent Plugins, используйте его документированный способ
установки пакета, а затем выполните setup-сценарий для передачи токена клиенту.
Клиентские адаптеры `.codex-plugin/`, `.cursor-plugin/`, `.claude-plugin/`,
`.agents/` и `.mcp.json` сохраняются для клиентов, которым нужен их собственный
формат. Они не являются заменой portable-файлам и не удаляются автоматически.

Bundled MCP в этих пакетах сохраняет прежний env-режим. В проектном режиме setup
выключает обнаруженную KIT-запись плагина только для выбранного проекта, по её
фактическому plugin/server identity; сами навыки остаются доступны. Если клиент не
позволяет установить identity или скрывает bundled-сервер от CLI, готовность не
подтверждается до проверки и локального выключения через `/mcp` или интерфейс
клиента. Offline-фикстуры не доказывают фактическую видимость plugin-инструментов.

Собственной песочницы у проекта нет. После подключения чтения и изменения обращаются к боевому магазину.

## Основной путь

1. Установите Node.js 20.11+, если он ещё не установлен.

2. Откройте терминал. На Windows используйте Windows Terminal, PowerShell или Command Prompt; на macOS и Linux — обычный терминал. Одна и та же команда работает во всех этих оболочках:

   ```bash
   npx skills@latest add ztemerbekov/a1-yandex-kit-skills -y
   ```

3. Явно вызовите навык `a1-yandex-kit-setup`. В Codex используйте:

   ```text
   $a1-yandex-kit-setup
   ```

   В другом AI-приложении явно выберите навык с этим именем в списке команд. Голосовая или текстовая фраза **«Подключи Яндекс KIT»** без явного выбора навыка установщик не запускает.

4. Если приложение нельзя определить автоматически, ассистент спросит, куда подключить магазин. В Codex и Claude Code он также определит корень выбранного проекта и покажет уже привязанный магазин, если он есть.
5. Setup-сценарий проверит Node.js и `npx` до запроса токена и изменения настроек. Существующую проектную привязку можно использовать во втором агенте без нового токена; прежнее пользовательское подключение можно перенести в выбранный проект.
6. Если нужен новый токен, получите его в кабинете продавца: **Настройки → API**. На локальном компьютере setup откроет страницу в постоянной штатной панели выбранного приложения, если такая возможность доступна: в Codex это браузерная панель приложения, в Claude Code — встроенная Browser/preview-панель. Временные вкладки автоматизации и управление экраном для этой страницы не используются, потому что они могут закрыться вместе с ответом ассистента. Если штатная панель недоступна или не может добраться до loopback, setup попробует браузер по умолчанию операционной системы, а при неуверенности даст ссылку для открытия вручную. Браузер и setup должны работать на одном компьютере: наличие встроенного браузера само по себе не доказывает доступ к loopback из удалённой или виртуальной сессии. В удалённой сессии используйте настройки секретов или окружения; чат-маршрут доступен только после явного выбора владельца. Ассистент не должен повторять токен в ответах или диагностике.
7. Токен, полученный через одноразовую страницу или явно выбранный чат-маршрут, будет проверен до сохранения настроек, чтобы убедиться в доступе к магазину. Неверный токен не записывается в конфиг.
8. После настройки сценарий проверит подключение выбранными для приложения документированными командами и read-only проверкой. Проверка подтверждает MCP-подключение и доступ к магазину, не меняя данные.
9. Проектная настройка сохраняет смысл существующих разрешений и запретов. В пользовательском режиме setup может отдельно предложить **«Работу без остановок»**. После согласия AI-приложение разрешит все текущие и будущие инструменты Yandex KIT без повторных Allow, включая удаления, заказы, промоакции и настройки магазина. Рабочие навыки по-прежнему выполняют изменения только по точной команде пользователя.
10. Если клиент нельзя перезагрузить документированной командой, ассистент даст одну короткую инструкцию по перезапуску.

Подключение считается завершённым только после сообщения, что проверка магазина прошла.

## Работа без повторных Allow

Подтверждения показывает само AI-приложение до вызова инструмента. Это отдельный
слой от токена Яндекс KIT и от разрешения, которое вы дали ассистенту своей
командой.

Проектная настройка Codex/Claude Code не включает и не предлагает server wildcard:
она переносит существующие целевые правила без расширения полномочий. Для этих
клиентов команды `approval-status` и `approval-configure` доступны только с явным
`--scope user` и отдельным запросом пользователя; они относятся к прежней
пользовательской записи.

В пользовательском режиме setup предупреждает о полном доступе к Yandex KIT и
предлагает server wildcard:

- Claude Code, Codex и Kimi Code настраиваются автоматически;
- Cursor настраивается автоматически только после проверки установленной схемы
  разрешений и фактического имени MCP-сервера;
- VS Code и Claude Desktop требуют одного шага в интерфейсе, если установленная
  версия умеет постоянно доверять всему MCP-серверу;
- Kimi Desktop, Hermes и embedded OpenClaw пока не умеют одновременно отключить
  остановки для импорта и сохранить отдельные подтверждения опасных действий.

После явного согласия setup включает wildcard только для управляемого сервера
Yandex KIT. В Cursor это `yandex-kit:*` и `user-yandex-kit:*`; в других клиентах
используется их эквивалент server-wide approval. Глобальный YOLO или Full access
для всех инструментов приложения не включается.

Проверить или повторно настроить этот режим можно тем же навыком
`a1-yandex-kit-setup`, сказав: **«Разреши все действия Yandex KIT без повторных Allow»**.

## Проектная привязка Codex и Claude Code

Один выбранный корневой каталог проекта соответствует одному магазину. Все новые
чаты этого проекта и оба агента используют общую привязку
`<project>/.yandex-kit/project.json`: версия формата и непрозрачный UUID
`connection_id`. Токен, ожидаемый `store_id`, название и адрес магазина хранятся
отдельно в `~/.a1-yandex-kit/connections/`. Секреты не попадают в проект или argv.

Корень можно явно задать через `--project-dir`; по умолчанию берётся текущий
рабочий каталог. Каталог установленного навыка проектом магазина не считается.
Для отдельного приватного хранилища есть `YANDEX_KIT_CONNECTIONS_DIR`: абсолютный
путь вне проекта и любого содержащего его Git-репозитория. Setup записывает этот
несекретный путь в MCP entry; обоим агентам нужен один и тот же корень.

- Codex: сервер `a1-yandex-kit-project` в `<project>/.codex/config.toml`.
- Claude Code: сервер с тем же именем в локальной записи
  `projects[absoluteProjectDir].mcpServers` файла `~/.claude.json`.
- `--scope user` явно возвращает Codex/Claude Code к прежней пользовательской
  настройке. Остальные клиенты используют её по умолчанию. Проектный Codex
  использует только `.codex/config.toml` выбранного проекта; произвольный
  `--config` относится к явному пользовательскому режиму.

При миграции setup проверяет реальную KIT-команду/пакет, оставляет глобальные
записи для других проектов и выключает обнаруженный старый экземпляр только в
выбранном проекте. Целевые allow/ask/deny и правила инструментов следуют за новым
именем без новых wildcard-разрешений. Если найдены разные магазины, нужно выбрать
фактически обнаруженный сервер через `--migrate-server`; первый вариант
автоматически не выбирается. Управляемая или неоднозначная политика остаётся
конфликтом для разрешения владельцем/администратором.

Setup проверяет эффективную конфигурацию нативным CLI из каталога проекта и
запускает runtime с `--project-config` для read-only `get_store`. Значение
`configured` в `status` означает согласованность файлов, а не готовность текущего
чата. Неизвестный формат ответа CLI, неустановленный identity плагина или активный
KIT-дубликат не считаются успешной проверкой.

После настройки, обновления токена или смены магазина начните новый чат Codex или
новую сессию Claude Code в этом проекте. Уже запущенный MCP-процесс сохраняет
прежнее подключение. Клон и worktree имеют собственный путь проекта: выполните
setup для каждого, даже если несекретная привязка скопировалась. Абсолютные пути
клиента нужно обновить; на другом компьютере нужна и приватная запись подключения.

## Повторный запуск, замена токена и смена магазина

В проектном режиме повторное подключение и добавление второго агента могут
использовать существующую привязку без токена. Явная замена токена запускает свежую
защищённую страницу и допускается только для того же `store_id`. Токен другого
магазина отклоняется до сохранения; страницу можно использовать для повторной
попытки. Смена магазина требует отдельного указания владельца и `--change-store`.
Она создаёт новое подключение и меняет привязку только выбранного проекта; прежняя
приватная запись сохраняется, поскольку её могут использовать другие копии.

В пользовательском режиме при существующем подключении ассистент спрашивает,
нужно ли обновить токен. Ответ «нет» завершает сценарий без изменения конфига;
ответ «да» открывает новую одноразовую страницу. Старую страницу не используют.
Чат-маршрут доступен только после явного выбора владельца.

## Запись и откат настройки

Проектный setup сохраняет секрет перед привязкой и клиентскими файлами, блокирует
конкурентные записи и проверяет ревизии. При ошибке проверки он откатывает только
собственные изменения; более новые правки сохраняются и дают конфликт отката.
Успешная изменившая настройку операция возвращает `transactionId` для явного
отката. Приватные журналы с прежними настройками/credentials лежат вне проекта в
`<connectionsRoot>/.setup-transactions/`. На POSIX приватные каталоги имеют права
`0700`, файлы — `0600`.

Пользовательский setup сохраняет резервную копию изменяемого конфига, права `0600`
на POSIX и откат по контрольным хешам. Если проектная запись `yandex-kit`
перекрывает пользовательскую, только этот прежний режим использует имя
`a1-yandex-kit-global` и оставляет локальную запись нетронутой.

Журналы и резервные копии относятся к подключению, а не к данным магазина.
Они не откатывают операции Яндекс KIT. Повреждённый формат настройки проходит
проверку совместимости; setup не исправляет его вслепую.

## Другой или изменившийся клиент

Для клиента без готового профиля используется последовательность:

1. документированная команда клиента для добавления MCP-сервера;
2. документированный пользовательский файл поддерживаемого формата;
3. техническая передача с найденной официальной документацией и точными следующими действиями.

Неизвестный формат не редактируется методом проб и ошибок. Полные правила находятся в [описании совместимости](../skills/a1-yandex-kit-setup/references/compatibility.md).

## Ручное подключение для специалиста

### Проектный режим (с 1.12.0)

При выполнении указанных выше требований к версиям setup формирует команду:

```text
npx -y mcp-yandex-kit@latest --project-config <absolute-project>/.yandex-kit/project.json
```

Сам токен передают helper только через защищённую страницу или stdin. Примеры
команд без секретов (замените `<skill-directory>` и `<project-root>`):

```bash
node "<skill-directory>/scripts/setup.mjs" configure --client codex --scope project --project-dir "<project-root>" --json
node "<skill-directory>/scripts/setup.mjs" token-web --client codex --scope project --project-dir "<project-root>" --json
node "<skill-directory>/scripts/setup.mjs" configure --client claude-code --scope project --project-dir "<project-root>" --json
node "<skill-directory>/scripts/setup.mjs" client-check --client codex --scope project --project-dir "<project-root>" --json
node "<skill-directory>/scripts/setup.mjs" smoke --client codex --scope project --project-dir "<project-root>" --json
node "<skill-directory>/scripts/setup.mjs" rollback --client codex --scope project --project-dir "<project-root>" --transaction <transactionId> --json
```

Первая команда использует привязку или проверенный вариант миграции, вторая нужна
при новом токене. Для неоднозначной миграции добавляют
`--migrate-server <detected-name>`, для явно запрошенной смены магазина —
`--change-store` к `configure` или `token-web`. В stdin-маршруте `configure`
получает `--token-stdin`. Для второго агента повторяют проверки с его `--client`.
Реальная приёмка четырёх клиентских проектов, Windows ACL и видимости bundled
плагинов ещё не выполнена; offline-тесты не заменяют её.

### Прежний пользовательский/env-режим

Без `--project-config` сервер использует прежнюю команду:

```text
npx -y mcp-yandex-kit@latest
```

В терминах конфигурации MCP нужны следующие значения:

```text
command: npx
args: -y, mcp-yandex-kit@latest
env: YANDEX_KIT_TOKEN=<токен магазина>
```

Формат и путь конфига зависят от клиента. Не вставляйте универсальный JSON-фрагмент в неизвестный файл: используйте официальную документацию приложения или проверенный профиль setup-сценария. Токен всё равно будет храниться в конфиге открытым текстом.

Доступные переменные окружения:

| Переменная | Обязательна | Значение по умолчанию | Назначение |
| --- | :---: | --- | --- |
| `YANDEX_KIT_TOKEN` | в env-режиме | — | API-токен; в проектном режиме игнорируется. |
| `YANDEX_KIT_BASE_URL` | нет | `https://api.kit.yandex.net` | URL только для env-режима; проектный runtime использует официальный API. |
| `YANDEX_KIT_CONNECTIONS_DIR` | нет | `~/.a1-yandex-kit/connections/` | Приватное хранилище проектных подключений вне репозитория. |
| `YANDEX_KIT_RPS` | нет | `3` | Лимит исходящих запросов в секунду. |
| `YANDEX_KIT_TIMEOUT_MS` | нет | `30000` | Таймаут одной попытки HTTP-запроса, мс. |

Не передавайте токен прямо в shell-команде: он может сохраниться в истории терминала.

## Обновление

Запись использует пакет `mcp-yandex-kit@latest`, поэтому при следующих запусках клиент разрешает актуальную опубликованную версию. Отдельная команда обновления MCP-сервера не требуется. Для проектного режима пакет и setup-навык должны соответствовать требованиям версии 1.12.0 или новее, указанным в начале инструкции. После обновления начните новую клиентскую сессию.

Новые версии и изменения публикуются в [GitHub Releases](https://github.com/ztemerbekov/a1-yandex-kit-skills/releases).

Доменный навык `a1-yandex-kit-marketing` переименован в
`a1-yandex-kit-promotions`. Если вы вызывали его явно через
`$a1-yandex-kit-marketing` или `/a1-yandex-kit-marketing`, замените имя на
`$a1-yandex-kit-promotions` или `/a1-yandex-kit-promotions`: старое имя больше не
поставляется.

## Если подключение не завершилось

- **Нет Node.js или `npx`.** Setup-навык не устанавливает Node.js. Установите актуальную LTS-версию [Node.js](https://nodejs.org/), перезапустите AI-приложение и снова явно вызовите `a1-yandex-kit-setup`.
- **Токен не прошёл проверку.** Создайте или скопируйте действующий токен в **Настройки → API** и передайте его повторно. Текущий конфиг до успешной проверки не меняется.
- **Конфиг повреждён или формат изменился.** Setup-сценарий не переписывает его вслепую: он проверит официальный CLI, документированный файл или подготовит техническую передачу.
- **Сервер подключён, но клиент его не видит.** Выполните ровно ту инструкцию по перезапуску, которую вернул setup-сценарий для выбранного клиента.
- **Конфликт старого KIT или bundled-плагина.** В проектном режиме нужно проверить локальное выключение фактически обнаруженной записи и эффективные инструменты в новой сессии. В прежнем пользовательском режиме при exact-name конфликте используется `a1-yandex-kit-global`.
- **Привязка отсутствует или магазин не совпал.** Проектный runtime останавливается без глобального токена и base URL; повторите setup для выбранного корня, не подменяя магазин неявно.
- **Конкурентное изменение или конфликт отката.** Сохраните новую правку и разберите диагностированный конфликт; принудительно перезаписывать файл или удалять lock не нужно.

Технические параметры сервера и сетевое поведение описаны в [TECHNICAL.md](TECHNICAL.md).
