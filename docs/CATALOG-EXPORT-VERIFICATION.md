# Проверка экспорта каталога

Оффлайн-набор для повторного прогона новым агентом после изменения скилла
каталога. Все ответы API ниже синтетические: запись в магазин не нужна. Проверяется
форма решения и факты в результате, а не точный текст сообщения агента.

## 1. Обычный экспорт каталога

Запрос владельца: «Выгрузи все товары в CSV».

Фикстура и синтетические ответы:

- `list_variants(all:true)` возвращает:

  ```json
  {
    "items": [
      {
        "id": "v-1", "name": "Кисть, большая", "sku": "SKU-1", "status": "PUBLISHED",
        "pricing": {"price": "1590.00", "final_price": "1490.00"},
        "stocks": [
          {"warehouse_id": "w-1", "quantity": 3, "reserved": 1},
          {"warehouse_id": "w-2", "quantity": 0, "reserved": 0}
        ]
      },
      {
        "id": "v-2", "name": "Без остатка", "sku": "SKU-2", "status": "HIDDEN",
        "pricing": {"final_price": null}, "stocks": []
      },
      {
        "id": "v-3", "name": "Товар без цены", "sku": "SKU-3", "status": "PUBLISHED",
        "pricing": {}, "stocks": [{"warehouse_id": "w-1", "quantity": 0, "reserved": 0}]
      }
    ],
    "coverage": "complete", "received": 3, "total_count": 3,
    "pages_read": 1, "pages": 1, "truncated": false
  }
  ```

- `list_warehouses(all:true)` возвращает `{ "items": [
  {"id":"w-1","title":"Основной склад","slug":"main","status":"ACTIVE"},
  {"id":"w-2","title":"Резервный склад","slug":"reserve","status":"ACTIVE"}
  ], "coverage":"complete", "received":2, "pages_read":1 }`. Если нужны понятные
  заголовки складов, этот снимок используется для каждой строки.
- `list_products` не вызывается. `format:"csv"` у `list_variants` не используется
  как готовый плоский экспорт, поскольку вложенные `pricing` и `stocks` попадут в
  JSON-ячейки.

Ожидаемые проверки результата (отдельно от фикстуры):

- Агент без уточняющего вопроса вызывает `list_variants`, получает CSV-файл с
  тремя строками данных, сообщает количество строк данных `3` и даёт ссылку на файл.
- В сообщении владельцу указан охват `PUBLISHED + HIDDEN` (без архивных) и то,
  что эта выборка полная; формулировка использует язык владельца.
- CSV имеет плоские колонки с локализованными заголовками, как минимум:

```text
Название,Артикул,Статус,Цена итоговая,Остаток — Основной склад,Резерв — Основной склад,Остаток — Резервный склад,Резерв — Резервный склад
"Кисть, большая",SKU-1,Опубликован,1490.00,3,1,0,0
Без остатка,SKU-2,Скрыт,,,,,
Товар без цены,SKU-3,Опубликован,,0,0,,
```

`Цена итоговая` берётся из `pricing.final_price`; отсутствующая или `null` цена
остаётся пустой. Для первого SKU выводятся `3` и `1`, для второго остаток
остаётся пустым/неизвестным, а не превращается в `0`. Ячейка с явным нулём для
первого и третьего SKU остаётся `0`. Значения цен и их единицы не пересчитываются.
Сначала идут понятные владельцу колонки названия, артикула, статуса и цены; технические
ID можно добавить в конце для трассировки. Заголовки и статусы локализуются для владельца,
а исходные API-поля используются только как внутренняя карта преобразования.

## 2. Явный технический дамп продуктов

Запрос владельца: «Выгрузи сырые продукты: id, group_id и category_ids для
сверки структуры».

Допустимый путь — `list_products(all:true, format:"csv", fields:["id",
"group_id", "category_ids"])`. Результат содержит product-group записи. Агент
не обогащает их вариантами без такого запроса: этот режим проверяет структуру,
а не продаваемые SKU.

## 3. Нулевой и неизвестный остаток

В фикстуре должны быть оба случая:

- `stocks: [{warehouse_id: "w1", quantity: 0, reserved: 0}]` → в CSV стоят
  `0` и `0`;
- `stocks: []` или отсутствует запись для `w1` → обе ячейки пустые/неизвестные.

Агент не выводит `quantity - reserved`, не подставляет ноль для отсутствующей
записи и не называет неизвестное значение фактом магазина.

## 4. Превышение лимита автопагинации

`list_variants(all:true)` возвращает `received: 500`, `pages_read: 5`,
`coverage: "partial"`, `total_count: 620`. Агент продолжает чтение с явной
страницы 6 (`per_page: 100`) до короткой/пустой хвостовой страницы, если это доступно, либо
создаёт CSV с честно указанным частичным охватом и сообщает, что он неполный.
Он не повторяет пять раз тот же `all:true` вызов и не говорит «все товары».

## Проверочный список

- [ ] Обычный запрос маршрутизирован к `list_variants`; вопрос product/variant не
      задавался.
- [ ] В CSV одна строка на variant/SKU, есть `name`, `sku`, `status`, явное
      отображение `pricing.final_price` и отдельные поля quantity/reserved по складам.
- [ ] Пустые/null значения сохранены как неизвестные; явный ноль сохранён как `0`.
- [ ] Владелец получил фактический статусный охват: по умолчанию PUBLISHED + HIDDEN,
      без ARCHIVED; `coverage: partial` не объявлен полной выгрузкой.
- [ ] Переданный владельцем status/product/name-фильтр сохранён; правило без фильтра
      применяется только к обычному запросу каталога.
- [ ] CSV с заголовком и осмысленными строками существует до сообщения о завершении.
- [ ] Имена с запятыми корректно заключены в кавычки по RFC 4180; количество строк указано
      числом и совпадает с количеством включённых variant-строк.
- [ ] `list_warehouses(all:true)` вызван не более одного раза для одного снимка и
      не повторяется без изменения данных.
- [ ] Технический product/group дамп выполняется только при явном запросе структуры;
      разницу числа products и variants агент не трактует как пропажу строк.
