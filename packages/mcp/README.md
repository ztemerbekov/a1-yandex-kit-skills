# `mcp-yandex-kit` — управляйте магазином через AI-ассистента

Подключите API [Яндекс KIT](https://kit.yandex.ru) к Claude, Cursor, Codex или другому MCP-клиенту и просто скажите, что должно получиться: показать заказы, обновить товары и остатки, создать скидку, промокод или вебхук. `mcp-yandex-kit` даёт ассистенту 61 готовый инструмент и доступ ко всем 151 операциям API — без ручной работы с HTTP-запросами и схемами.

- **Полное покрытие API.** 65 операций доступны через специализированные инструменты, остальные — через `search_operations`, `get_operation_schema` и `kit_request`.
- **Запуск через `npx`.** Сервер не нужно устанавливать отдельно; понадобится Node.js 20+.
- **Проверка до отправки.** Тела write-запросов валидируются по JSON Schema сохранённой OpenAPI-спецификации до обращения к сети.
- **Без слепых повторов.** Автоматически повторяются только GET-запросы; POST, PATCH, PUT и DELETE после сетевой ошибки не запускаются повторно.
- **Бережно к лимитам KIT.** Встроенный клиент по умолчанию ограничивает поток до 3 запросов в секунду и учитывает `Retry-After`.

После подключения попробуйте:

> Покажи заказы за сегодня и их статусы оплаты.

## Быстрый старт

### 1. Получите токен

В кабинете продавца Яндекс KIT откройте **Настройки → API → «Сгенерировать токен»**. Скопируйте токен сразу: он показывается только один раз.

> **Токен даёт полный доступ к магазину и хранится открытым текстом в конфиге MCP-клиента. Относитесь к нему как к паролю: не добавляйте его в репозиторий, публичный файл или лог.**

### 2. Добавьте сервер в AI-клиент

<details open>
<summary><strong>Codex</strong></summary>

```bash
codex mcp add yandex-kit \
  --env YANDEX_KIT_TOKEN=ваш_токен \
  -- npx -y mcp-yandex-kit@latest
```

Начните новую задачу Codex, чтобы клиент загрузил сервер.

</details>

<details>
<summary><strong>Claude Code</strong></summary>

```bash
claude mcp add yandex-kit \
  -e YANDEX_KIT_TOKEN=ваш_токен \
  -- npx -y mcp-yandex-kit@latest
```

Начните новую сессию Claude Code.

</details>

<details>
<summary><strong>Cursor</strong></summary>

Добавьте сервер в `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "yandex-kit": {
      "command": "npx",
      "args": ["-y", "mcp-yandex-kit@latest"],
      "env": {
        "YANDEX_KIT_TOKEN": "ваш_токен"
      }
    }
  }
}
```

Перезагрузите окно Cursor.

</details>

<details>
<summary><strong>Другой MCP-клиент</strong></summary>

Используйте локальный транспорт `stdio` и следующие параметры:

```text
command: npx
args: -y, mcp-yandex-kit@latest
env: YANDEX_KIT_TOKEN=<токен магазина>
```

Формат и путь конфига зависят от клиента. Используйте официальную документацию приложения, а не вставляйте универсальный JSON-фрагмент в неизвестный файл.

</details>

### 3. Проверьте подключение

Спросите ассистента:

> Проверь, подключился ли магазин. Покажи, сколько товаров в каталоге, и скажи, на что стоит обратить внимание в первую очередь.

Если ассистент видит магазин и каталог, сервер готов к работе.

## MCP-сервер или полный комплект

`mcp-yandex-kit` — это прямой доступ к API Яндекс KIT. Он предоставляет инструменты, а решение о том, какие из них и в какой последовательности вызвать, принимает AI-клиент.

Если вы хотите не набор инструментов, а готового оператора магазина, установите [A1 Yandex KIT Skills](https://github.com/ztemerbekov/a1-yandex-kit-skills). Навыки добавляют поверх MCP-сервера рабочие сценарии и правила: обзорные запросы ничего не меняют, бизнес-значения не придумываются, а результат разрешённого изменения читается повторно и проверяется.

```bash
npx skills@latest add ztemerbekov/a1-yandex-kit-skills -y
```

После установки напишите ассистенту обычными словами:

```text
Давай подключим мой магазин.
```

Ассистент определит текущее приложение, попросит токен и проверит подключение.

Готовые сценарии включают операционный разбор магазина, аудит и исправление каталога, запуск промо и проверку готовности к открытию.

> **Вы:** Создай коллекцию «Я чувствую тебя» и перекинь туда всё, что связано с парфюмом.
>
> **Ассистент:** Создал активную коллекцию и добавил в неё три парфюма. Из прежних коллекций товары не удалял.

## Как устроено покрытие API

Сервер предоставляет **61 MCP-инструмент**. У повседневных задач есть специализированные инструменты с понятными аргументами; вместе они покрывают **65 из 151 операции** сохранённой спецификации Яндекс KIT.

Для остальных 86 операций используется мета-трио:

1. `search_operations` — находит операцию по ключевому слову, `operationId`, пути, тегу или русскому описанию.
2. `get_operation_schema` — возвращает HTTP-метод, путь, параметры, content type и развёрнутые схемы запроса и ответа.
3. `kit_request` — выполняет выбранную операцию по `operationId`.

Так ассистент получает удобные инструменты для частых задач, но не упирается в их фиксированный список, когда нужна редкая операция API.

## Настройка

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | :---: | --- | --- |
| `YANDEX_KIT_TOKEN` | да | — | API-токен магазина. |
| `YANDEX_KIT_BASE_URL` | нет | `https://api.kit.yandex.net` | Базовый URL API. |
| `YANDEX_KIT_RPS` | нет | `3` | Лимит исходящих запросов в секунду. |
| `YANDEX_KIT_TIMEOUT_MS` | нет | `30000` | Таймаут одной попытки HTTP-запроса, мс. |

Технически сервер работает через `stdio` и использует Bearer-токен. Для каждого запроса применяется content type из спецификации, включая `application/merge-patch+json` и `multipart/form-data`.

## Обратите внимание

- **Все вызовы идут в рабочий магазин.** Собственной песочницы у проекта нет.
- **Токен хранится открытым текстом.** Не передавайте конфиг другим людям и не публикуйте его.
- **`kit_request` может изменять данные.** Безопасность зависит от операции, выбранной ассистентом.
- **Write-запросы не повторяются автоматически.** После таймаута изменение могло уже примениться; слепой повтор создал бы дубликат или вторую мутацию.
- **Лимит API — 3 запроса в секунду на магазин.** `LIMIT_EXCEEDED` может прийти с HTTP 400, а не 429; клиент учитывает этот ответ при повторах GET-запросов.
- **API Яндекс KIT находится в статусе беты.** Контракт может меняться.
